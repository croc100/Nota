# 0003. 연주 순서와 악보 위치를 분리한다

- 상태: 제안 (구현 전)
- 날짜: 2026-11-05

## 발견

`ScoreGeometry`는 악보상 위치(박)를 캔버스 y로 매핑하면서 `anchors_`를 **단조
증가로 강제**한다. 박이 늘면 y는 반드시 늘어난다.

**도돌이로 같은 구간을 다시 연주하면 y가 되돌아가야 하는데, 구조상 표현할 수
없다.**

얼마나 흔한 문제인지 코퍼스 표본으로 확인했다.

| 곡 | 반복 기호 | 박자표 종류 |
|---|---|---|
| Bach BWV846 | 0 | 1 |
| **Chopin Op.6-2** | **10** | 1 |
| Mozart K155 1악장 | 0 | 1 |
| Beethoven Op.18-1 1악장 | 4 | 1 |
| Haydn Op.1-1 1악장 | 12 | 1 |
| Schumann Op.41-1 1악장 | 8 | **2** |

**6곡 중 4곡(67%)에 반복이 있다.** 그중 Chopin Op.6-2는 지금까지 모든 검증에
써 온 곡이고, 반복 기호가 10개다.

### 왜 지금까지 드러나지 않았나

지금까지의 측정은 두 종류였다.

- **V1/V2 (검출 정확도)** — 오선·시스템·마디를 이미지에서 찾는 정확도.
  연주 순서와 무관하므로 **이 수치들은 여전히 유효하다.**
- **매핑 오차 (드리프트 0박)** — 악보를 처음부터 끝까지 **한 번만 쭉 친다는
  가정** 아래 계산했다. 반복이 있는 곡에서는 그 가정이 깨진다.

즉 "드리프트 0박"은 틀린 값이 아니라 **좁은 조건에서의 값**이다. 연주 순서는
한 번도 검증한 적이 없다.

## 원인

두 개의 서로 다른 축을 하나로 뭉쳐 놓았다.

| 축 | 성질 |
|---|---|
| **악보 위치** — 페이지의 어디인가 | 단조. 같은 위치는 한 곳뿐 |
| **연주 시간** — 실제로 친 순서 | 같은 악보 위치를 여러 번 방문 |

`ScoreGeometry`는 전자를 다루는 자료구조인데 후자의 입력(연주 중 경과한 박)을
받고 있다.

## 결정

**`ScoreGeometry`는 그대로 둔다.** 악보 위치 ↔ 캔버스 좌표를 다루는 층으로서는
올바르고, 단조성도 그 층에서는 참이다.

그 위에 **연주 순서 층**을 얹는다.

```
연주 시간(박)
     │
     ▼
┌─────────────────────────────┐
│ PerformancePlan             │  악보의 어느 구간을 어떤 순서로
│ [구간1, 구간2, 구간2, 구간3]  │  지나는지. 반복은 같은 구간의 재등장
└──────────────┬──────────────┘
               │ 악보 위치(박)
               ▼
┌─────────────────────────────┐
│ ScoreGeometry (기존 그대로)   │  악보 위치 ↔ 캔버스 y, 단조
└─────────────────────────────┘
```

연주 시간 → 구간 → 악보 위치 → 캔버스 y. 같은 구간이 계획에 두 번 나오면 y는
자연히 되돌아간다. 기존 코드를 다시 쓰지 않는다.

## 구현 범위

1. **반복 기호 검출** — 겹세로줄 + 점 두 개. 지금의 마디선 검출을 확장하면
   된다. 굵은 선과 얇은 선의 조합, 그 옆의 점 두 개가 특징이다.
2. **연주 계획 생성** — 검출된 반복 기호로 기본 계획을 만든다. 관례대로
   한 번 반복을 기본값으로 둔다.
3. **사용자 조정** — 반복을 할지 말지는 연주자가 정한다. 자동 판정보다
   사용자가 미리 지정하는 쪽이 확실하다 (`DESIGN.md` 7절의 완화 전략 5).
4. **박자표 변화** — 지금은 곡 전체에 `beats_per_measure` 하나를 쓴다.
   마디별 박 수를 받도록 넓힌다. 표본의 1/6에서 이미 발생한다.

### 하지 않는 것

**오디오만으로 "지금 몇 번째 반복인가"를 판정하지 않는다.** 같은 음악이
같게 들리므로 원리상 어렵고, 틀리면 악보가 엉뚱한 곳으로 뛴다. 사용자가
미리 정하거나, 반복 구간에서는 추적을 느슨하게 하는 편이 안전하다.

## 영향

- 기존 `ScoreGeometry` API와 테스트는 그대로 유효하다
- `ScrollController`도 그대로다. 입력이 연주 시간인지 악보 위치인지만 바뀐다
- 매핑 오차 측정(`evaluate_geometry.py`)은 연주 순서를 반영하도록 넓혀야 한다
- V6(드리프트) 기준은 반복이 있는 곡에서 다시 정의해야 한다
